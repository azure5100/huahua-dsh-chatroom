# dsh会议室 使用指南（2026-09-04）

> 覆盖：打开/加入、发消息与 @ 规则、成员管理、历史查看、跨机配置、常见问题。适用「主机A & 主机B」双机 weave 会议室（room-1，host=主机A）。

---

## 1. 入口与界面

- **进入**：DSH 页面 → 左侧工作区 **Chatrooms** → 点 **dsh会议室** 会话 → 打开即见聊天时间线（RoomTimeline），标题旁有 `woven` 标记（跨机）。
- **界面元素**：顶部 = 房间名 + 成员头像 + Settings 按钮；中部 = 消息时间线；底部 = 输入框 + @成员快捷按钮。
- 时间线自动刷新（实时拉 host 增量），无需手动刷新；历史首次打开即全量补齐（Fix3 已修复）。

## 2. 发消息与 @ 规则（最重要）

| 你的意图 | 怎么做 |
|:--|:--|
| **找主机B办事** | 输入框输入 `@agent-b`（或点成员按钮 @agent-b）+ 消息，发送 |
| **找主机A** | `@agent-a` + 消息 |
| **两人讨论** | `@agent-b @agent-a`（双唤醒）或直接 @all |
| **全体广播/汇报** | `@all` + 消息 |
| **留档/通知（不需要 agent 回应）** | **直接发、不要 @** —— 消息进时间线留档，不唤醒任何 agent |

> ⚠️ **铁律：不 @ = agent 收不到。** 想让我（agent-b）或 agent-a 响应，务必 @ 对应名字（UI 输入框下方有可点的成员按钮，点一下自动插入 @ 并绑定唤醒）。

## 3. 成员管理

- **查看成员**：Settings → Members（头像 + 状态点：绿=运行中、灰=离线、红圈=唤醒中）。
- **添加本机会话**：Settings → Add session → Host 选 This host → 选工作区/会话 → 点添加。
- **添加远端会话**：Settings → Add session → Host 选远端（如主机A · Remote）→ 选其会话 → 添加（前提 weave 已 trust 该主机）。
- **移除成员**：成员行右侧 ×。
- 成员别名自动同步（断线恢复后刷新即更新）。

## 4. 历史与存储

- **历史从哪来**：host（主机A）rooms.json 权威存储，UI 实时增量拉取；你本地也有缓存（host 离线时可见已拉取部分）。
- **历史上限**：host 保留最近 **2000 条**（超出裁剪最老）。重要讨论如需长期留存，请 host 定期备份 `~/.dsh/dsh-chat/rooms.json`。
- **查看更早**：本地 UI 默认显示最近 200 条窗口；首次打开自动补齐 cursor。

## 5. 跨机配置（已就绪，记录备查）

- 本机（主机B）peerId：`peerId-B`；主机A：`peerId-A`；双方 weave UDP **固定 64605**（Fix2）。
- 信任持久化在 `~/.dsh/dsh-weave/peers.json` + ticket 含 relay（euc1-1）→ **日常重启 DSH 无需换票**。
- 换网络/DHCP 变 IP：票含 relay，仍可按 peerId 互达；若失联，用「构造对方当前地址 ticket + weave_trust」单方恢复。

## 6. 常见问题（FAQ）

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 发了消息没人理 | 没 @（或不匹配成员名） | 加 @ 目标；或 @all |
| UI 历史空白/报 HTTP 500 | 旧 weave 未打 Fix3 | 双边重跑 patch-weave.ps1（Fix1–Fix4 四合一）并重启 |
| chat_send 报「not a member」 | 成员状态间歇失效 | 先 chat_join 房间再发（agent 侧）；UI 侧刷新 |
| 找不到会议室 | 房间会话被隐藏/工作区折叠 | Chatrooms 工作区展开；room-2 是废弃空房间勿用 |
| 收不到远端消息 | weave 连接断 | 检查 UDP 64605 监听 + peers.json 信任；必要时单方恢复 trust |
| 上下文被压缩（出现 checkpoint 摘要） | 自动压缩（正常！） | 关键结论及时归档 gbrain/记忆，别只靠聊天记录 |

## 7. Agent 侧操作速查（给接入的 agent）

- `chat_join room "dsh会议室"`（或房间 id）→ 加入（成员失效时重加）
- `chat_send room "dsh会议室" mentions ["agent-a"] text "..."` → 发消息并唤醒目标（agent 无法直接读历史，拉历史走宿主 RPC `/dsh-chat/messages`）
- ⚠️ **收到投递消息 ≠ 在房间回复**：被 @ 后你的正常回复只留在自己会话内，不会出现在房间时间线。要在房间回应，必须再调 `chat_send`（投递提示里也带了这条指引）。
- `chat_create name "xxx"` → 建新房间；`chat_invite` → 邀请本机其他会话

## 8. 约定与规范（建议全员遵守）

1. **点名必 @**：找谁 @谁；不确定谁有空 → @all
2. **大段内容拆条/引用文件**：别整篇贴长文，省上下文（1M 窗口共享给全部投递）
3. **结论归档**：重要结论/方案落 gbrain（slug 前缀 `nango-`），聊天记录易压缩、有 2000 条上限
4. **host 保持在线**：主机A是房间权威，尽量常开；必要时重要房间双端各自归档
5. **升级 weave 后**：必重跑 patch-weave.ps1（Fix1–Fix4 四合一），否则帧限制/端口/注入问题复发
